# 🐧 리눅스 프로세스 & 작업 예약 관리

## 1. 프로세스 (Process)

### ⚙️ 개요

- **정의**: 실행 중인 프로그램 (메모리에 로딩되어 CPU를 할당받는 상태)
- **특징**: 리눅스는 멀티 프로세스 시스템으로 여러 개의 프로세스를 동시에 실행
- **유형**: 운영에 필요한 시스템 프로세스 + 사용자가 실행한 사용자 프로세스
- **부모-자식 관계**:
    - 필요에 따라 부모가 자식을 생성 (`fork`)
    - 자식은 또 다른 자식 생성 가능
    - **부모 없는 프로세스 (최상위)**: 부팅 시 스케줄러가 실행한 `systemd`(1번), `kthreadd`(2번)
    

### 🔢 프로세스 번호 (PID)

- **PID (Process IDentifier)**: 각 프로세스의 고유 번호
- **할당 규칙**: 1번부터 시작하며 실행 시 1씩 증가
- **주요 PID**:
    - `1번`: **systemd** (유닉스의 init 기능을 대체, 우분투 기준)
    - `2번`: **kthreadd**
    

### 📋 프로세스 종류

> **1. 일반 프로세스**
> 
> - 자신이 수행할 작업을 전부 수행하면 종료됨

> **2. 데몬 프로세스 (Daemon)**
> 
> - 특정 서비스를 제공하기 위해 커널에 의해 실행됨 (서비스라고도 함)
> - 평소에는 대기(`Listen`) 상태, 요청 시 서비스 제공
> - 서버라고 불리는 서비스는 거의 데몬 형태

> **3. 고아 프로세스 (Orphan)**
> 
> - 자식 프로세스가 아직 실행 중인데 부모가 먼저 종료된 경우
> - 리눅스는 **1번 프로세스(systemd)**를 새로운 부모로 지정하여 작업을 마치고 안전하게 종료되도록 함

> **4. 좀비 프로세스 (Zombie)**
> 
> - 자식 프로세스가 종료되었으나, 부모 프로세스가 종료 정보(Exit Status)를 회수하지 않아 프로세스 테이블에 남아있는 상태
> - 프로세스 목록에 `defunct`라고 표시됨
> - **문제점**: 쌓이면 테이블이 가득 차서 새 프로세스 생성 불가
> - **해결**: `kill`로 삭제 불가. 부모에게 `SIGCHLD` 시그널을 보내거나 부모 프로세스를 종료해야 함

## 2. 프로세스 관리

### 🔍 프로세스 목록 확인 (`ps`)

- **형식**: `ps [옵션]`

| **옵션 종류** | **옵션** | **설명** |
| --- | --- | --- |
| **Unix** | `-e` | 실행 중인 모든 프로세스 확인 |
|  | `-f` | 자세한 정보 출력 (Full) |
|  | `-u uid` | 특정 유저가 실행한 것만 확인 |
|  | `-p pid` | PID에 해당하는 정보 확인 |
| **BSD** | `a` | 터미널과 연관된 프로세스 |
|  | `u` | 소유자 정보를 포함한 상세 정보 |
|  | `x` | 터미널에 종속되지 않은 프로세스 포함 |

**사용 예시**

```bash
ps -a
ps -au
ps -ef | grep bash  # 주로 많이 사용
```

### 🛑 프로세스 종료 (`kill`)

- **개요**: 프로세스에 시그널(Signal)을 보내서 종료
- **명령어**: `kill`, `pkill`, `killall`
- **형식**: `kill [-시그널] PID`

**주요 시그널 (`kill -l`로 확인 가능)**

- `2` (SIGINT): 인터럽트 (CTRL+C 와 동일)
- `9` (SIGKILL): **강제 종료**
- `15` (SIGTERM): 정상 종료 (관련 파일 정리 후 종료, 종료 안 될 수 있음)

**실습 예제**

```bash
# 터미널 1
man ls

# 터미널 2
ps -fp $(pgrep -x man)   # man의 PID 확인
# 또는 ps -ef | grep man
kill [PID]               # 프로세스 종료
```

- **pkill**: 프로세스 이름으로 종료 (동일 이름 모두 종료)
- **killall**: pkill과 유사

### 📊 주기적 모니터링

- **`top`**: 시스템 상태와 프로세스 정보를 실시간으로 주기적으로 출력

## 3. 작업 제어 (Job Control)

| **구분** | **설명** | **예시** |
| --- | --- | --- |
| **Foreground** (동기식) | 명령 실행 후 결과가 나올 때까지 대기 | `sleep 100` |
| **Background** (비동기식) | 명령 끝남과 상관없이 즉시 프롬프트 반환 | `sleep 100 &` |

**백그라운드 작업 특징**

- 시간이 오래 걸리거나, 실행 후 다른 작업을 해야 할 때 사용
- **출력 처리**: 화면 출력이 겹칠 수 있으므로 리다이렉션 사용 권장

```bash
find / -name passwd > pw.dat 2>&1
# 에러 메시지(2)도 표준 출력(1)과 함께 pw.dat에 저장
```

### 📑 작업 목록 관리 (`jobs`)

백그라운드 작업을 조회합니다.

- **형식**: `jobs [%작업 번호]`
- **상태 표시**:
    - `+`: 가장 최근 접근한 작업
    - : 바로 전 작업
    - `Running`: 실행 중
    - `Stopped`: 일시 중지됨 (Ctrl+Z)
    - `Done` / `Terminated`: 완료 / 강제 종료

**출력 예시**

```bash
jobs
[1]+  Running                 sleep 100 &
```

### 🔄 작업 전환 및 용어

- **`CTRL + z`**: 포그라운드 작업 **일시 중지** (종료 아님)
- **`bg %작업번호`**: 중지된 작업을 백그라운드로 전환 (실행 재개)
- **`fg %작업번호`**: 작업을 포그라운드로 가져옴

**주요 용어 (Terms)**

- **Context Switching**: 프로세스 교환 (많이 발생하면 속도 저하)
- **Overhead**: 실제 일하는 시간보다 관리/전환에 쓰는 시간이 많음
- **Thrashing**: 오버헤드가 너무 커서 시스템 성능이 급격히 떨어지는 현상

**실습 예제**

```bash
sleep 200        # 포그라운드 실행
^Z               # CTRL+Z로 중지
# [1]+  Stopped                 sleep 200

bg %1            # 백그라운드로 전환
# [1]+ sleep 200 &

fg %1            # 다시 포그라운드로 가져옴
# sleep 200

nohup 명령 &     # 로그아웃 후에도 계속 작업하기
```

### 🚫 작업 종료

- **Foreground**: `CTRL + c` (인터럽트 시그널 전송)
- **Background**: `kill %작업번호` 또는 PID 찾아서 종료
- **로그아웃 후 유지**: `nohup 명령어 &`

## 4. 작업 예약 I - 일회성 (`at`)

### ⏰ 정해진 시간에 한 번만 수행

- **명령어**: `at [옵션] [시각]`
- **데몬**: `atd` (데몬이 실행 중이어야 함)

**옵션**

- `l`: 대기 중인 목록 출력 (`atq`와 동일)
- `d` / `r`: 작업 삭제 (`atrm`과 동일)
- `m`: 결과 없어도 메일 발송
- `f 파일`: 파일에 적힌 명령 실행

**시간 설정 예시**

- `at 4pm + 3days`: 3일 후 오후 4시
- `at 10am Jul 31`: 7월 31일 오전 10시
- `at 1am tomorrow`: 내일 오전 1시
- `at now + 3 minutes`: 지금으로부터 3분 뒤

### 🛠️ 실습 및 파일 관리

**작업 파일 생성 및 예약**

```bash
# 1. 간단 예약
at 12:47 am
at> /usr/bin/ls > ~seongyun/at.out
at> (CTRL + d)

# 2. 파일로 예약
vim at.sh
# (내용 작성: 
# date > ~seongyun/test.txt 
# ls >> ~seongyun/test.txt)
chmod 777 at.sh    # 실행 권한 필수!
at -f ~seongyun/at.sh 1:23
```

**작업 확인 및 삭제**

```bash
at -l
atq              # 목록 확인

at -d
atrm [작업번호]   # 삭제

sudo ls -l /var/spool/cron/atjobs  # 실제 저장 위치 확인
```

### 🔐 사용 제한 (Access Control)

관리자는 파일로 `at` 사용 권한을 제어할 수 있습니다.

1. `/etc/at.allow`: 여기에 적힌 사용자만 사용 가능 (**우선순위 높음**)
2. `/etc/at.deny`: 여기에 적힌 사용자는 차단 (allow 파일이 없을 때 적용)
3. **규칙**:
    - `allow` 존재 O: `deny` 무시, `allow` 명단만 사용 가능
    - `allow` 존재 X: `deny` 명단 제외하고 모두 사용 가능
    - 둘 다 존재 X: `root`만 사용 가능
    - *초기 설정: 빈 `at.deny` 파일만 존재 (모든 사용자 허용)*

## 5. 작업 예약 II - 주기적 반복 (cron)

### 🔄 Crontab 개요

- **기능**: 사용자가 지정한 시간에 작업을 주기적으로 반복 실행
- **구조**: 사용자별로 별도의 파일 생성, 한 줄에 하나의 작업 설정
- **형식**: `crontab [-u 사용자ID] [옵션]`

**주요 옵션**

| **옵션** | **설명** | **비고** |
| --- | --- | --- |
| **`-e`** | crontab 파일 **편집** (Edit) | ✏️ 가장 많이 사용 (vi 에디터 실행) |
| **`-l`** | crontab 파일 **목록 출력** (List) | 📋 현재 예약된 작업 리스트 확인 |
| **`-r`** | crontab 파일 **삭제** (Remove) | ⚠️ **주의**: 모든 예약 작업이 즉시 삭제됨 |

### 📝 설정 방법 및 문법

터미널에 `crontab -e` 입력 후 편집기에서 작성합니다.

**시간 설정 구조 (5자리 + 명령어)**

```bash
#  분    시    일    월    요일   |   실행할 명령어
   42    1     *     *      *        ls -l > ~seongyun/cron.out
```

*(해석: 매일 새벽 1시 42분에 ls 명령 실행)*

**필드별 범위 및 의미**

1. **분 (Minute)**: 0 ~ 59
2. **시 (Hour)**: 0 ~ 23
3. **일 (Day of Month)**: 1 ~ 31
4. **월 (Month)**: 1 ~ 12
5. **요일 (Day of Week)**: 0 ~ 6 (0: 일요일, 1: 월요일, ... 6: 토요일)

**특수 문자 활용**

| **기호** | **의미** | **예시** |
| --- | --- | --- |
| **`*`** | **모든 값** (All) | 매분, 매시간, 매일 무조건 실행 |
| **`-`** | **범위 지정** (Range) | `1-5` (월요일부터 금요일까지) |
| **`,`** | **목록 지정** (List) | `1,3,5` (1시, 3시, 5시에만 실행) |
| **`/`** | **간격** (Step) | `*/20` (20분 간격), `1-10/2` (1~10분 사이 2분 간격) |

### 📂 관련 파일 및 로그

- **작업 파일 위치**: `/var/spool/cron/crontabs` (계정당 하나씩 존재)
- **로그 확인**:
    - 기본적으로 우분투는 cron 로그가 비활성화됨
    - **활성화 방법**: `sudo service rsyslog restart` 수행 후 `/var/log/cron.log` 파일 확인

### 🚀 확장: 현업 연관 기술

리눅스 cron 개념은 최신 기술 스택에서도 스케줄링의 근간이 됩니다.

- **Kubernetes CronJob**: 컨테이너 환경에서 주기적인 배치 작업 실행
- **Airflow (Python)**: 데이터 엔지니어링에서 복잡한 워크플로우 스케줄링
- **Spring Batch**: 대용량 데이터 일괄 처리를 위한 프레임워크
