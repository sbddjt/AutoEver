# 📘 OOP (Object Oriented Programming)

> **객체 지향 프로그래밍**: 프로그래밍을 명령어의 목록으로 보는 시각에서 벗어나, 여러 개의 독립된 단위인 '객체'들의 모임으로 파악하고자 하는 패러다임

## 1. 프로그래밍 패러다임의 변화

* **구조적 프로그래밍 (C언어 등)**
* 블록(Block) 단위로 프로그램을 구성.
* 협업 시 각 블록을 **파일 단위**로 묶어서 관리.


* **객체 지향 프로그래밍 (C++, Java, Python, Go, TypeScript 등)**
* 구조적 프로그래밍을 포함하는 더 넓은 개념.
* 코드와 데이터를 **클래스, 라이브러리, 패키지** 단위로 묶어서 관리 및 협업.



> **💡 언어별 특징 (Pointer/Reference)**
> * **C++**: `this`, `super`와 같은 예약어가 내재되어 있음.
> * **Python**: 인스턴스 자신을 가리키는 키워드로 `self`를 명시적으로 기재함.

## 2. 객체 지향의 4대 특징

### 📦 1) Encapsulation (캡슐화)

* **정의**: 데이터(속성)와 그 데이터를 처리하는 함수(메서드)를 하나로 묶는 것.
* **핵심**: 클래스(Class)라는 틀을 만들고, 이를 통해 인스턴스(Instance)를 생성하는 과정 자체가 캡슐화의 시작.

### 🧬 2) Inheritance (상속)

* **정의**: 상위 클래스의 모든 요소를 하위 클래스가 물려받는 것.
* **주 목적**: **중복 제거** 및 코드 재사용.
* **특징**:
* **사고의 전환**: 상위에서 하위로 내려가는 것이 아니라, 하위 클래스들이 공통분모인 **상위 클래스를 가리키도록(참조하도록)** 설계하는 것이 효율적.
* **유지보수**: 상위 클래스만 수정하면 모든 하위 클래스에 적용되므로 실수가 줄어듦.
* **Subclassing**: 원래 있던 클래스에 새로운 기능을 추가하여 확장하는 방식.
* **Framework & Library**: 기본적인 구조(Class)는 유지하되, 요소들의 변형(Instance/Subclass)을 통해 기능을 구현.



### 🎭 3) Polymorphism (다형성)

* **정의**: 동일한 코드가 호출하는 대상(객체)에 따라 다른 작업을 수행하는 것.
* **비유**: **마우스 클릭**
* 클릭이라는 동작은 같지만, 어떤 아이콘 위에서 클릭하느냐(환경/대상)에 따라 실행되는 기능이 달라짐.


* **장점**: 과거 명령어 기반 시스템에서는 모든 명령어를 외워야 했으나, GUI와 다형성의 결합으로 사용성과 구현 난이도가 낮아짐.
* **참고**: Python은 클래스보다 인스턴스의 유연성이 매우 커서 타 언어에 비해 다형성의 경계가 모호해 보일 수 있음.

### 🌫️ 4) Abstraction (추상화)

* **정의**: 세부 사항은 숨기고, 사용자에게 필요한 **핵심 기능(인터페이스)**만 노출하는 것.
* **특징**:
* 껍데기(인터페이스/템플릿)만 존재하고 실제 구현은 하위에서 담당하도록 설계.
* **Template Programming**: 복잡한 내부 로직은 감추고 표준화된 틀을 제공하여 사용자가 쉽게 코드를 짤 수 있게 함.
