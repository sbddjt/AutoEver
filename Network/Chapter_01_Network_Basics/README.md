# 🌐 네트워크 기본 (Network Basics)

## 1. 기본 개념

### 1) Protocol (프로토콜)

**📡 개요**

- 규정이나 규약과 관련된 내용.
- 프로토콜은 어떤 표준 협회나 워킹 그룹이 만들었는지 또는 어떤 회사에서 사용하느냐에 따라 특징이 많이 달라지고 다양한 프로토콜이 존재.
- **최근 추세**: 복잡하고 산재되어 있던 여러 가지 프로토콜 기술이 **이더넷 - TCP/IP** 기반 프로토콜들로 변경되고 있음.
    - 🔌 **물리적 측면**: 데이터 전송 매체, 신호 규약, 회선 규격 등으로 **이더넷(Ethernet)**이 널리 쓰임.
    - 🧠 **논리적 측면**: 장치들끼리 통신하기 위한 프로토콜 규격으로 **TCP/IP**가 널리 쓰임.
- **목표**: 적은 컴퓨팅 자원과 느린 네트워크 속도를 이용해서 최대한 효율적으로 통신하는 것이 목표. 따라서 대부분의 프로토콜이 문자 기반이 아닌 **0️⃣1️⃣ 2진수 bit 기반**으로 만들어짐.

**0️⃣1️⃣ Bit 기반 vs 📝 문자(Text) 기반**

- **Bit 기반 (효율성 중심)**
    - 몇 번째 전기 신호는 보내는 사람 주소, 몇 번째는 받는 사람 주소, 몇 번째는 상위 프로토콜 지시자 등과 같이 까다롭게 약속함.
    - 그 약속을 철저히 지켜야 통신을 할 수 있음 (IP, TCP 등).
- **문자 기반 (확장성 중심)**
    - 애플리케이션 레벨(사용자)에서는 비트 기반이 아닌 문자 기반 프로토콜을 사용 (**HTTP, SMTP** 등).
    - 비트로 메시지를 전달하지 않고 문자 자체를 이용해 헤더와 헤더 값 데이터를 표현하고 전송.
    - 효율성은 비트 기반 프로토콜보다 떨어지지만 다양한 확장이 가능함.
    

> **🖥️ HTTP 프로토콜의 헤더 예시**
> 
> 
> 애플리케이션 층의 프로토콜은 문자로 되어 있으며 헤더에서 다양한 정보를 얻을 수 있음.
> 
> ```html
> GET /api HTTP/1.1
> Accept: text/html, application/xhtml+xml, /
> Referer: http://zigispace.net/ (어디를 통해서 들어왔는지 - 네이버, 구글 등)
> Accept-Language: ko-KR
> User-Agent: Mozilla/5.0 (Windows NT 6.1...) like Gecko
> Host: theplmingspace.tistory.com
> Connection: Keep-Alive
> ```
> 

**(참고) 🍎 MAC(Apple) programming**

- `Protocol`이라는 개념을 사용함.
- **Interface**: 추상 메서드만 소유한 개체.
- **추상 메서드**: 반드시 하위 클래스에서 **재정의(Implementation)** 해야 한다.

## 2. OSI 7계층과 TCP/IP

### 1) 구조 및 특징

**📚 TCP/IP 프로토콜 스택**

<img width="660" height="325" alt="Image" src="https://github.com/user-attachments/assets/48873070-c713-4bd2-8f40-a8393f756970" />

- TCP/IP는 프로토콜이라 부르지 않고 **프로토콜 스택**이라고 부름.
- TCP와 IP는 별도 계층에서 동작하는 프로토콜인데 함께 사용하기 때문에 묶어서 표현하는 경우가 많음.
- TCP/IP 프로토콜 스택에는 TCP, IP, UDP, ICMP, ARP, HTTP, SMTP, FTP와 같은 매우 다양한 애플리케이션 레이어 프로토콜이 존재.
- **4개 계층으로 구분**:
    - **Application**: FTP, SSH, TELNET, DNS, SNMP
    - **Transport**: TCP, UDP
    - **Network**: IP, ICMP, ARP
    - **Data Link & Physical**: Ethernet
    

**🏗️ OSI 7계층**

<img width="660" height="325" alt="Image" src="https://github.com/user-attachments/assets/77ab2d26-8777-4926-a614-2e158cee692c" />

- 과거에는 통신용 규약이 표준화되지 않고 각 벤더에서 별도로 개발했기 때문에 호환되지 않는 시스템이나 애플리케이션이 많았고 통신이 불가능했음. 이를 하나의 규약으로 통합하려는 노력이 **OSI 7계층**.
- 네트워크의 동작으로 나누어 이해하고 개발하는데 많은 도움을 주어서 주요 레퍼런스 모델로 활용하고 있지만, 최근에는 대부분의 프로토콜이 TCP/IP 프로토콜 스택을 기반으로 되어 있음.
- **계층 구분**:
    - **하위 계층 (1~4계층)**: Network Engineer 입장에서 중요.
    - **상위 계층 (5~7계층)**: Application Developer 입장에서 중요.

## 3. 계층별 심화 이해

### 🔌 1계층 (Physical - 물리)

**1. 개요**

- **초점**: 물리적 연결과 전기 신호 전달.
- **특징**: **허브(Hub)**는 주소 개념이 없어, 들어온 포트를 제외한 **모든 포트에 신호를 전송(Flooding)**함.

**2. 주요 장비**

- **종류**: Hub, Repeater, Cable, Connector, Transceiver, TAP

> 💡 **실무 포인트: TAP (Network TAP)**
> 
> - **정의**: 네트워크 모니터링이나 패킷 분석을 위해 **전기 신호를 복제**하는 장비.
> - **용도**: Web Server의 트래픽 로그 분석을 위해, 서비스 중단 없이 로그 서버로 트래픽을 똑같이 복제할 때 사용.

---

### 🔗 2계층 (Data Link - 데이터 링크)

**1. 개요**

- **처리**: 전기 신호를 모아 데이터 형태(**Frame**)로 변환.
- **초점**: **정확한 주소 통신**.
- **주소 체계**: **MAC Address** 사용.

**2. 핵심 기능 및 장비**

- **기능**: 출발지/목적지 주소 확인, 에러 탐지 및 수정.
- **장비**: **NIC** (네트워크 인터페이스 카드), **Switch**.

**(참고) 심화 이해: Hub vs Switch & Virtualization**

- **Hub(1계층) vs Switch(2계층)**
    - **Hub (Dummy)**: 🧠 지능 없음. 무조건 모든 포트로 뿌림 (**Always Flooding**).
    - **Switch (Intelligent)**: 💡 지능 있음. **MAC 주소**를 식별함.
        - **Learning**: 출발지 주소를 보고 테이블에 기록.
        - **Forwarding**: 목적지 주소를 알면 해당 포트로만 보냄.
        - **Flooding**: 목적지 주소를 모를 때(초기)만 전체 전송.
    
- **☁️ 클라우드(Kubernetes) 중요성**
    - **가상 스위치**: 물리 스위치 대신 리눅스 커널의 **'리눅스 브릿지'**가 파드(Pod) 간 통신 담당.
    - **🛠️ 트러블슈팅**: 통신 장애 시 가상 스위치가 **MAC 주소를 제대로 학습했는지** 확인하는 것이 핵심.

---

### 🚦 3계층 (Network - 네트워크)

**1. 개요**

- 🌐 **주소**: **논리적 주소(IP)** 사용. (네트워크 vs 호스트 구분)
- 🛣️ **핵심 역할**: 경로 설정 (**Routing**).

**2. 라우터 (Router)의 역할**

- **정의**: 서로 다른 네트워크를 연결하는 중계 장치.
- **Path Determination**: 목적지까지 가는 **최적의 경로 탐색** (네트워크의 내비게이션 🗺️).
- **Switching**: 패킷을 적절한 출력 포트로 전달.

**3. 서브넷 마스크를 기억하는 이유**

- **구분**: IP 주소에서 **'네트워크(동네)'**와 **'호스트(집)'**를 나누기 위함.
- **효율성**: 개별 IP 대신 네트워크 대역(Prefix) 단위로 저장해 **메모리 절약**.
- **게이트웨이 판단**: 내부망 통신인지 외부(인터넷) 통신인지 결정.

**4. 라우팅 테이블과 최적 경로**

- **용량 제한**: 라우터 **메모리(RAM)**에 따라 저장 가능한 경로 수 제한.
- **Metric (메트릭)**: 최적 경로를 선정하는 점수 기준 (거리, 속도, 지연 시간 등).

> **☁️ (참고) 심화 이해: 클라우드와 VPC**
> 
> - **AWS VPC**: 물리 네트워크를 논리적으로 격리한 **사용자 전용 가상 네트워크**.
> - **실무 설계**: `IP 대역(CIDR) 설정` → `서브넷 분리` → `라우팅 테이블 규칙 설정`의 3단계 흐름.

---

### ⚓ 4계층 (Transport - 전송)

**1. 개요**

- **역할**: 데이터 정상 전송 확인 및 **애플리케이션(프로세스) 구분**.
- **주요 장비**: Load Balancer, Firewall.

**2. 핵심 기능**

- **🧩 패킷 조립/분해**: 데이터를 일정 단위(Segment)로 쪼개고 번호(Sequence) 부여.
- **🎮 제어**: **ACK(응답)**를 이용해 흐름 제어 및 에러 복구.

**3. 포트(Port)와 PID**

- **개념**: 컴퓨터 내 특정 **프로세스**를 식별하기 위한 논리적 주소.
- **특징**: 사용자 설정 가능. OS 내부의 **PID**와 바인딩되어 동작.

**4. ⚖️ L4 로드밸런서 & 🛡️ 방화벽**

- **Load Balancer**: **[IP + Port]** 기준. 트래픽을 분산하여 **가용성** 확보.
- **Firewall**: **[IP + Port]** 기준. 패킷을 통과/차단하여 **보안 정책** 수립.

---

### 📞 5계층 (Session - 세션)

**1. 개요**

- 🤝 **초점**: 양 끝 단의 응용 프로세스가 **연결을 성립**하도록 돕고, 안정적으로 **유지 및 관리**하며, 작업 완료 후 **연결을 끊는** 역할을 수행.
- **기능**: 통신 중 끊김 발생 시 **에러 복구**와 **재전송**을 담당 (동기화 점/체크포인트 관리).

**(참고) 심화 이해: 세션 유지의 메커니즘**

**1. 🔑 세션(Session) vs 🍪 쿠키(Cookie)**

- **데이터 보관의 차이**
    - **세션 (서버)**: 사용자 데이터의 **원본**과 이를 식별할 **해시값(Session ID)**을 모두 가지고 있음. (🏦 자물쇠 + 열쇠 보관)
    - **쿠키 (클라이언트)**: 서버의 원본 데이터를 찾기 위한 **해시값(Session ID)**만 가지고 있음. (🗝️ 열쇠만 보유)
- **통신 원리**
    - 클라이언트가 통신할 때마다 쿠키에 담긴 해시값을 서버에 **'태워서'** 보냄.
    - 서버는 이를 자기 메모리의 원본 데이터와 대조하여 사용자를 식별함.
    

**2. 🍪 쿠키의 한계와 💾 로컬 스토리지(Local Storage)**

- **쿠키의 단점**
    - 매번 전송 시마다 헤더에 데이터를 담아 보내므로 **네트워크 부하**가 발생.
    - 저장 용량이 매우 작음 (약 4KB).
- **로컬 스토리지의 등장**
    - 클라이언트(브라우저)에만 데이터를 저장하고 **서버로 자동 전송하지 않음**.
    - 쿠키보다 훨씬 큰 용량(약 5MB+)을 제공하며, 필요한 경우에만 꺼내 쓰므로 **효율적**임.
    - **클라이언트에서만 관리하는 정보**를 담기에 최적화된 공간.
    

**3. 💾 로컬 스토리지 vs 🗄️ IndexedDB (브라우저 내장 DB)**

- **로컬 스토리지 (Local Storage)**
    - **특징**: 단순 Key-Value 저장 방식. 사용이 매우 간편함.
    - **용도**: 사용자 설정(테마, 언어), 간단한 상태값 저장.
- **브라우저 내장 DB (IndexedDB)**
    - **특징**: 브라우저 기반 NoSQL 데이터베이스. 대용량 저장 및 인덱스 검색 가능.
    - **용도**: 오프라인 웹 앱(PWA), 복잡한 구조의 데이터, 대량의 객체 저장.

---

### 🎨 6계층 (Presentation - 표현)

**1. 개요**

- **역할**: 표현 방식이 다른 애플리케이션이나 시스템 간의 통신을 돕기 위해, 데이터를 **동일한 형식으로 변환(Translation)**시키는 역할.
- **비유**: 한국인과 미국인이 대화할 때 중간에서 통역사가 언어를 번역해 주는 것과 같음.

**2. 주요 기능**

- **인코딩 (Encoding)**: 데이터를 시스템이 이해할 수 있는 포맷으로 변환 (예: ASCII, UTF-8 등).
- **암호화 (Encryption)**: 데이터의 보안을 위해 전송 전 암호화 및 수신 후 복호화 수행.
- **압축 (Compression)**: 전송 효율을 높이기 위해 데이터의 크기를 줄임.

---

### 🖥️ 7계층 (Application - 응용)

**1. 개요**

- **역할**: 사용자가 네트워크에 접근할 수 있도록 **인터페이스(UI)**를 제공하는 **최상위 계층**.
- **기능**: 사용자로부터 데이터를 입력받거나(Input), 처리된 데이터를 사용자에게 보여주는(Output) 부분을 정의.

**2. 주요 서비스 및 프로토콜**

- **실제 서비스 구동**: 우리가 흔히 사용하는 프로그램들이 통신할 때 사용하는 규약.
- **예시**:
    - **HTTP/HTTPS**: 웹 서핑 (브라우저).
    - **FTP**: 파일 전송.
    - **SMTP**: 이메일 전송.
    - **SSH**: 원격 접속.
