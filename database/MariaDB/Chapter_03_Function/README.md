# 📊 [DB] MariaDB 내장 함수(Function) 완벽 정리

## 1. 함수(Function) 개요

### 1.1 정의

> Input(데이터) ➡️ Process(연산) ➡️ Output(결과값)
> 
- **개념:** 입력 데이터를 이용하여 연산을 수행한 후, **하나의 결과 값**을 만들어 내는 개체
- **구조:**
    - **입력:** Argument (Parameter, 매개변수, 인수)
    - **출력:** Return Data (반환값)

### 1.2 함수의 분류

| **분류 기준** | **종류** | **설명** | **매핑 관계** |
| --- | --- | --- | --- |
| **매개변수** | **Scala 함수** | 단일행 함수. 입력값 하나당 결과값 하나 | 1:1 |
| (데이터 수) | **Group 함수** | 집계 함수. 여러 입력값을 묶어 통계 계산 | N:1 |
| **기능** | **유형별** | 문자, 수치, 날짜, 제어, 정보, 암호 함수 등 | - |

## 2. 🛠 실무 활용 핵심 함수 (Practical Functions)

### 🔤 문자열 함수 (String Functions)

**1. 문자열 결합 (`CONCAT`)**

- `CONCAT(str1, str2)`: 문자열을 이어 붙임.

> 💡 강사님 Tip (실무)
> 
> 
> 게시판 제목 등이 너무 길 때, SQL단에서 앞부분만 자르고 '...'을 붙여서 가져오면 프론트엔드 처리가 간편해집니다.
> 

```sql
SELECT CONCAT(LEFT(name, 3), ' . . . ') 
FROM user_tbl;
```

**2. 대소문자 변환 (`UPPER`, `LOWER`)**

> 💡 강사님 Tip (검색 기능 구현)
> 
> 
> 사용자가 대/소문자 중 무엇을 입력할지 예측할 수 없습니다. **비교 시 한쪽으로 통일(Normalization)**하여 검색 정확도를 높여야 합니다.
> 

```sql
- 이름을 모두 대문자로 변환하여 비교
SELECT *
FROM EMP 
WHERE UPPER(name) = 'SCOTT';
```

**3. 기타 유용한 함수**

- **공백 제거 (`TRIM`):** `LTRIM`(좌), `RTRIM`(우), `TRIM`(양쪽)
- **문자열 추출 (`SUBSTRING`):** `SUBSTRING(문자열, 시작위치, 길이)`
    - *활용:* `HIREDATE`에서 연도나 월만 추출할 때 사용.

### 🔢 수치 및 날짜 함수

| **구분** | **함수** | **설명** |
| --- | --- | --- |
| **수치** | `ROUND` / `CEILING` / `FLOOR` | 반올림 / 올림 / 내림 |
|  | `MOD(n1, n2)` | 나머지 연산 (예: 사원 번호 홀수/짝수 판별) |
| **날짜** | `NOW()`, `SYSDATE()` | 현재 날짜와 시간 반환 |
|  | `ADDDATE` / `SUBDATE` | 날짜 더하기 / 빼기 |
|  | `DATEDIFF(date1, date2)` | 두 날짜 간의 차이(일수) 계산 |

## 3. 🚦 제어 흐름 및 NULL 처리 (★중요)

> 👨‍🏫 Insight: 개발 트렌드의 변화 (DB vs Backend)
> 
> - **과거:** DB 쿼리 내에서 복잡한 로직(IF, CASE 등)을 처리하는 경우가 많았음.
> - **현재:** Full-stack 협업 환경에서는 **Application Level(Java, Python)**에서 로직 처리를 선호.
> - **결론:** 사용 빈도는 줄었으나, **레거시 시스템 유지보수**나 **타인의 쿼리 분석**을 위해 필수로 알아야 함.

### 3.1 NULL 처리 함수

수치 연산 시 `NULL`이 포함되면 결과가 무조건 `NULL`이 되므로 치환이 필수적입니다.

- **`IFNULL(값1, 값2)`**SQL
    - 값1이 NULL이 아니면 `값1`, NULL이면 `값2` 반환 (Oracle의 `NVL`과 유사).
    - *활용:* 보너스(COMM)가 NULL일 때 0으로 계산.
    
    ```sql
    SELECT ENAME, IFNULL(COMM, 0) 
    FROM EMP;
    ```
    
- **`NVL2(식, 값1, 값2)`**
    - 식이 NULL이 아니면 `값1`, NULL이면 `값2` 반환.

### 3.2 제어 흐름 함수

- **`IF(조건, 참, 거짓)`**: 엑셀의 IF와 동일 (2중 분기).
- **`CASE WHEN ... THEN ... END`**: 다중 분기 처리 (Switch-Case와 유사).

## 4. 🔄 데이터 타입 변환 (Type Conversion)

1. **묵시적 형 변환:** 시스템이 문맥을 보고 자동 변환.
    - *예:* `'100' + '200'` → 문자열이지만 산술 연산 시 숫자로 자동 변환.
2. **명시적 형 변환:** 사용자가 함수를 써서 강제 변환.
    - `CAST(값 AS 데이터타입)`
    - `CONVERT(값, 데이터타입)`
    - `TO_CHAR`: 날짜/시간 → 문자열

> ⚠️ 주의 (DBMS 특징)
> 
> 
> MySQL/MariaDB 계열에서는 VARCHAR 타입으로의 CAST 형 변환을 지원하지 않는 경우가 많으니 주의해야 합니다.
>

## 5. 🚀 [심화] 저장 구조와 성능: CHAR vs VARCHAR

> 핵심 주제: 개발자는 알고리즘을 중시하지만, DBA는 저장 공간 최적화와 I/O 성능을 최우선으로 봅니다.
> 

### 5.1 비교 분석

| **특징** | **CHAR (고정 길이)** | **VARCHAR (가변 길이)** |
| --- | --- | --- |
| **저장 방식** | 지정된 길이만큼 무조건 공간 확보 | 실제 데이터 길이만큼만 저장 + 길이 정보 |
| **공간 효율** | 데이터가 짧으면 낭비 발생 (Padding) | 공간 효율이 좋음 |
| **UPDATE 성능** | **유리함** (길이 변화에 유연) | **불리함** (길이가 늘어나면 문제 발생) |

### 5.2 🚨 Row Migration (행 이주) 현상

- **상황:** `VARCHAR`로 저장된 짧은 데이터('ADAM')를 긴 데이터('STEVE_JOBS')로 수정(Update) 시도.
- **문제:** 처음에 딱 맞게 공간을 할당했으므로, 늘어난 데이터를 저장할 공간이 부족함.
- **결과:** 데이터를 저장할 **새로운 페이지**를 찾아 이동시키는 **Row Migration** 발생 → **Disk I/O 증가로 성능 저하.**

### ✅ 5.3 실무 적용 가이드 (강사님 추천)

1. **자주 바뀌는 데이터 👉 `CHAR` 사용**
    - *예:* 비밀번호(PW), 코드값 등.
    - *이유:* 내용이 자주 변경되어도 CHAR는 이미 공간을 확보해 두었으므로 Row Migration 오버헤드가 없음.
2. **거의 바뀌지 않는 데이터 👉 `VARCHAR` 사용**
    - *예:* 아이디(ID), 게시글 내용, 주소 등.
    - *이유:* 생성 후 길이가 변할 일이 적으므로, 저장 용량을 절약하는 것이 효율적.
